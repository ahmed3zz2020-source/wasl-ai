## ٣. ⭐ كتالوج الحزم المرشّحة (WASl Pack Catalogue v0)

### ٣.١ معايير الاختيار (مرئية ومُعاد إنتاجها)

الحزمة مرشّحة لو اجتازت **3 من 4**:
1. **كثافة المحادثة**: النشاط بيسبب محادثات خدمة/بيع على واتساب بكثافة عالية.
2. **قابلية الأتمتة**: أغلب الأسئلة متكرّرة وقابلة للإجابة من معرفة النشاط.
3. **عدم الحساسية التنظيمية**: مش محتاج ترخيص أو التزام مالي صارم في V1.
4. **حجم السوق**: شريحة SME عربية كبيرة.

## ٤. ⭐ دورة «إضافة نشاط جديد» — المically معدّلة

```
١. العميل يطلب نشاط
        ↓
٢. البحث في الكتالوج (٣٣ مرشّح)
        ├── ✅ موجود كحزمة ⇒ تخصيص (ساعات)
        └── ❌ غير موجود
              ↓
٣. البحث في سجل القدرات (سجل القدرات)
        ├── ✅ القدرة موجودة ⇒ ⭐ حزمة جديدة تُؤلَّف (أيام)
        └── ❌ غير موجودة ⇒ ⭐ مسار تطوير القدرة (أسبوع)
                                  ↓
                       ④ تُضافCapability ⇒ تُتاح لكل الحزم
                                  ↓
                       ⑤ حزمة جديدة تُؤلَّف وتُختبر
```

**⏰ الزمن الموعود للعميل**:
| الحالة | الوعد |
| النشاط موجود كحزمة | **ساعة** |
| القدرة موجودة ⇒ حزمة جديدة | **أيام** (٢–٥ أيام عمل) |
| محتاج قدرة جديدة | **أسابيع** (١–٣ أسابيع) + **سعر مخصص** |

> ⛔ **ممنوع** وعد «من غير برمجة» أو «أي نشاط في يوم». الوعد بأيام ⇒ صادق.
> ⛔ **سعر مخصص** لو محتاج قدرة جديدة ⇒ بيغطي تكلفة التطوير (سؤال **س-١٤** مفتوح للمالك).

## ٥. ⭐ ضوابط الوراثة وتثبيت الإصدارات (تصحيح R004 #4)

### ٥.١ وراثة الحزم

| الضابط | القاعدة |
| **العمق** | ⛔ أقصى ٣ مستويات (`extends` متسلسل) |
| **حدود الأمان** | ⛔ الابن **مش** يقدر يرفع `limits` (مثل `max_value` أو `per_day`) فوق حد الأم · حد الأم = السقف الأعلى |
| **الحذف** | ⛔ وراثةCapability جديدة **ما بتمسحش** أي قدرة موروثة. لو Ability بقت غير لازمة ⇒ `deprecated` مش محذوفة |
| **التوافق** | كل حزمة ابن **لازم** يمرّ على بوابة النشر بنفس شروط الأم (eval suite) |
| **التحديث** | تحديث الأم **مش** بيعدّل الحزم الأبناء تلقائياً ⇒ الأبناء **مثبّتة** |

### ٥.٢ تثبيت الإصدارات (Pinning)

```
manifest العميل (Tenant Manifest)
├─ pack:      restaurant @ 1.2.0        ← مثبّت
├─ workflows: restaurant.order @ 1.1.0  ← مثبّتة
├─ capabilities:
│    order.create @ 2.1.0               ← مثبّتة
│    catalog.read @ 1.4.2               ← مثبّتة
│    payment.initiate @ 0.9.0           ← مثبّتة
└─ prompts:   agent.system @ 3.1.0      ← مثبّت
```

**القواعد**:
- ⛔ **مفيش ترقية تلقائية.** العميل الم pins ⇒ نسخته هي اللي شغّالة.
- ⭐ الترقية = **فرق مرئي** (ايه اللي اتغيّر في الحزمة/المسار/القدرة) ⇒ **موافقة صريحة**.
- ⭐ **سجل يدوي**: مين رقّى مين إمتى وبأي سبب.
- ⛔ **الإهمال (deprecation)**: لما القدرة تتشال ⇒ الترقية إجبارية للعملاء المتأثرين ⇒ إشعار + مهلة.
