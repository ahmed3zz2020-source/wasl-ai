## ⭐ ١. الخطأ الواحد — صلاحية `workflow`

### ⭐ ١.١ الرسالة كما ظهرت (مقيسة · ٢٦ نوفمبر ٢٠٢٦)

```text
remote rejected probe/workflow-scope -> probe/workflow-scope
(refusing to allow a Personal Access Token to create or update workflow
`.github/workflows/ci.yml` without `workflow` scope)
```

### ⭐ ١.٢ التشخيص

- ⭐ **التوكن الحالي (`ahmed3zz2020-source`) بلا صلاحية `workflow`** ⇒ ⭐ **فأي دفعة تلمس `.github/workflows/` مرفوضة بالكامل**.
- ⭐ **الكود نفسه سليم**: ⭐ **الملفات الأربعة موجودة ومحفوظة داخل commit `9688b2f`** ⇒ ⭐ **فالمشكلة إذن واحدة لا غير: إذن التوكن**.
- ⭐ **ما ورد في الدفعة رفضها**: ⭐ **`.github/workflows/ci.yml` و `release-check.yml` و `scripts/compare-baseline.py` و `scripts/no-secret-check.py`** ⇒ ⭐ **وهي محفوظة على القرح في هذه البيئة أيضاً**.
- ⭐ **الأثر**: ⭐ **لا خط CI على أي push** ⇒ ⭐ **وبند `pf-23` يبقى مفتوحاً** ⇒ ⭐ **والحراس (الأرقام المنشورة · عدّ الاختبارات · التوثيق) تعمل يدوياً فقط**.

### ⭐ ١.٣ ما يفعله المالك بالضبط (خطوتان)

**الخطوة ١ — صلاحية واحدة + سرّ واحد:**

- ⭐ **Personal Access Token جديد (أو محدَّث) لنفس الحساب `ahmed3zz2020-source`** ⇒ ⭐ **بصلاحية `workflow`** (أو Granular Access بصلاحية Workflows: write).
- ⭐ **وفي إعدادات المستودع: سرّ جديد اسمه `WASL_CI_POSTGRES_PASSWORD`** ⇒ ⭐ **وهو سرّ واحد فقط** ⇒ ⭐ **والسرّ لا يدخل المستودع ولا السجل**.

**الخطوة ٢ — إرجاع ملفات الـCI (سطران):**

```bash
cd /workspace/wasl-ai
git checkout 9688b2f -- .github/workflows
git add -f .github/workflows
git commit -m "ci: the workflows are back"
git push origin main
```

> ⭐ **لو أعطيت المشرف التوكن الجديد** ⇒ ⭐ **ينفّذ السطرين هما وبس** ⇒ ⭐ **وإلا نفّذهم بنفسك على أي نسخة من المستودع**.
