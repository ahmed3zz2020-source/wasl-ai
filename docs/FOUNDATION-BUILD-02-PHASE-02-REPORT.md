## ٠. الملخّص التنفيذي

⏺️ PHASE 02 عالجت **ست ملاحظات** (M66–M71) بإصلاحات تقنية حقيقية
ومسنودة باختبارات، كلها محلية على PostgreSQL وNode.js الحقيقية.

⭐ **النتيجة**: **٧٢٤ اختباراً · ٧٢٤ ناجح · ٠ فاشل · ٠ متخطّى** (مقابل
٦٨٧ في خط الأساس) · الرحلة E2E **١٥/١٥** · **صفر سطر** في `src/core`.

| الملاحظة | العيب | الإصلاح | النتيجة |
|:-:|---|---|:-:|
| ⭐ M66 | نسخة Backend قد تقرأ محادثة قديمة من ذاكرتها | PostgreSQL صار مصدر الحقيقة: الباقة أصبحت **لكل عملية** والقفل **قبل** القراءة | ٨ اختبارات |
| ⭐ M67 | اشتقاق المفتاح كان **يسدّ** حلقة الأحداث وعدّاد واحد فقط | scrypt **غير متزامن** + ميزانية **عامة** للمنصّة + دور **حيّ** | ٧ اختبارات |
| ⭐ M68 | دليل الحذف كان قابلاً للتعديل، ولا وسيلة لمعرفة النتيجة بعد فقدان الرد | الدليل **غير قابل للتغيير** + **تجزئة** + **إيصال** | ٩ اختبارات |
| ⭐ M69 | النسخة كانت نصاً صريحاً على القرص بلا فحص سلامة | **تشفير AES-256-GCM** + **بيان** (manifest) + **قياس** زمن الاستعادة | ٦ اختبارات |
| ⭐ M70 | لا Dockerfile ولا compose قابل للتشغيل | صورة **بمستخدم غير جذر** + compose محلي + **فحص جاهزية** + **إيقاف سلس** | ٦ اختبارات |
| ⭐ M71 | نتيجة واحدة مبهمة لكل الاختبارات | **أربع مجموعات** منفصلة + **مصفوفة** + تكرار + إعادة بناء | ٧٢٤ |

⭐ **تغيير معلن واحد**: بعد M67 صار **حدّ التخمين يرفض التخمين لا
صاحبه** ⇒ كلمة المرور الصحيحة تُقبل دائماً ⇒ لا يستطيع أحد تعطيل
حساب غيره بهجوم متعمّد. المعالجة السابقة (رفض كلمة المرور الصحيحة
أثناء تفعيل الحدّ) كانت موثّقة في تقرير Phase 01 ⇒ **تغيير معلن**
موثّق هنا.

⭐ **قرار خطير لم يُتخذ**: بناء صورة Docker **لم يحدث** ⇒ البيئة
الحالية **لا تملك** Docker ⇒ الجاهزية للاستضافة **غير مثبتة** بهذا
البند (تفصيلها في §٩).

## ٢. جدول M66–M71

### ⭐ M66 — اتساق القراءة والكتابة بين نسختَي Backend

| البند | التفصيل |
|---|---|
| ⭐ العيب | الباقة (bundle) كانت تعيش **مدّة حياة العملية**: محادثة تُحمَّل مرة لا تُقرأ ثانية ⇒ نسخة ثانية تعمل على محادثة قديمة. والرسالة المكرّرة كانت **تُسقَط بصمت** بـ`on conflict do nothing` بينما الـAPI يجيب `201` |
| ⭐ السبب الجذري | `bundle.hydrated` كان ذاكرة عملية (process cache) + ترتيب القراءة **قبل** القفل |
| ⭐ الإصلاح | ① الباقة أصبحت **لكل عملية** (لا ذاكرة مشتركة) ② `lockConversationRow` (قفل `for update`) **قبل** التحميل ③ تعارض الرسالة صار **مرفوضاً** (`message_conflict` ⇒ `409`) لا مهملاً ④ محادثة بلا رسائل لم تعد "مفقودة" |
| ⭐ الاختبار | `tests/server/foundation-consistency.test.ts` · M-66a..M-66g (٨) |
| ⭐ النتيجة | **٨/٨** · و**M-66a وM-66c يفشلان على الكود القديم** (مُثبَت بالـstash) ⇒ الاختبار يمسك العيب فعلاً |
| ⭐ القيد المتبقّي | الاتساق **read-committed + تسلسل على مستوى الصف** داخل PostgreSQL. لا يوجد تسلسل على مستوى الطلب (serializable) ⇒ لا ترتيب بين **محادثات مختلفة** (وهو غير مطلوب) |
| ⭐ المخاطر | ⛔ لا يوجد versioning للمشاهد (snapshot isolation) ⇒ قراءة متسقة عبر عدة استعلامات ليست مضمونة، وكل قراءة في الـAPI **استعلام واحد** |

### ⭐ M67 — حماية الدخول والضغط على الخادم

| البند | التفصيل |
|---|---|
| ⭐ العيب | `scryptSync` كان **يسدّ حلقة الأحداث** ⇒ دفعة من محاولات الدخول توقف الخدمة كلها · وعدّاد واحد (لكل حساب) لا يوقف هجوماً **موزّعاً على حسابات كثيرة** · ودور الجلسة كان **لقطة** ⇒ تغيير الدور لا يسري إلا بانتهاء الجلسة |
| ⭐ السبب الجذري | اشتقاق متزامن + عدّاد محدود بحدود الشركة + `s.role` بدل `m.role` |
| ⭐ الإصلاح | ① `verifyPasscodeAsync` (‏`crypto.scrypt` على خيط libuv) — **نفس الصيغة ونفس التكلفة** ⇒ كلمات المرور القائمة تعمل ② **ميزانية عامّة** (`login_attempts_global`) عبر دالتين `SECURITY DEFINER` ضيّقتين ③ **عنوان المقبس** فقط — `X-Forwarded-For` **لا يُقرأ أبداً** ④ **الدور الحيّ** من صف العضوية |
| ⭐ الاختبار | `tests/server/foundation-auth-protection.test.ts` · M-67a..M-67f (٧) |
| ⭐ النتيجة | **٧/٧** · تأخّر حلقة الأحداث < ٢٥٠ مللي ثانية أثناء ٨ اشتقاقات · فحص الصحة يبقى **٢٠٠** أثناء ١٢ تخميناً |
| ⭐ القيد المتبقّي | ⚠️ خلف reverse proxy كل الطلبات تحمل **عنوان الوسيط** ⇒ ميزانية العنوان **معطّلة افتراضياً** (`WASL_LOGIN_TRUST_PEER_ADDRESS=0`) ⇒ الحدّ الشبكي يكون عند الوسيط لا عند التطبيق |
| ⭐ قرار المالك | ⚠️ **سياسة قفل الحساب** (المدة · الإشعار · فتح يدوي) **لم تُتخذ**:هذه قرار المالك، والتنفيذ أضاف العدّادات والرؤية فقط |

### ⭐ M68 — سلامة دليل الحذف

| البند | التفصيل |
|---|---|
| ⭐ العيب | الدليل كان قابلاً لـ`UPDATE`/`DELETE` ⇒ يمكن إعادة كتابته بعد التنفيذ · والعميل الذي فقد رده كان يقرأ "طلب غير معروف" ⇒ أي فقدان يقرأ كـ"لم يحدث شيء" |
| ⭐ السبب الجذري | جدول `tenant_deletion_evidence` بلا حماية للتغيير · وبلا وسيلة لقراءة النتيجة بعد فقدان الرد |
| ⭐ الإصلاح | ① **تجزئة محتوى** يحسبها **قاعدة البيانات** (`sha256` المدمج) ② **حارس عدم التغيير**: لا `UPDATE` ولا `DELETE` حتى لدور المالك ③ **إيصال**: دالة `SECURITY DEFINER` تقول `executed / previewed / unknown` وتكشف التلاعب ④ **معرّف طلب ١٢٨ بت** يحمل الشركة ⇒ هو **القدرة** على قراءة الإيصال ⑤ إعادة الإرسال **لا تحذف مرتين** |
| ⭐ الاختبار | `tests/server/foundation-deletion-receipt.test.ts` · M-68a..M-68h (٩) |
| ⭐ النتيجة | **٩/٩** · التلاعب المميّز يكشفه الإيصال (`verified=false`) |
| ⭐ القيد المتبقّي | ⛔ **مدة احتفاظ الدليل قرار مالك**: الحارس غير قابل للتجاوز ⇒ لا يمكن حذف دليل قديم إلا بإسقاط الحارس يدوياً · ⛔ التجزئة **كشف** التلاعب ولا **تمنع** من يُعطّل الحارس — الحماية الحقيقية هي **عدم التغيير** |

### ⭐ M69 — النسخ الاحتياطي والاستعادة

| البند | التفصيل |
|---|---|
| ⭐ العيب | النسخة **نص صريح** على القرص (نسخة كاملة من القاعدة خارج الحماية) · **لا فحص سلامة** ⇒ نسخة تالفة أو مستبدلة تُستعاد كأنها سليمة |
| ⭐ السبب الجذري | `pg_dump` إلى ملف عادي بلا تشفير · لا بيان (manifest) · لا تحقّق |
| ⭐ الإصلاح | ① **تشفير AES-256-GCM** والملف الصريح **يُحذف** بعده ② **بيان** لكل نسخة: تجزئة الملف الصريح · تجزئة القطعة المشفّرة · الحجم · إصدار المخطط · **بصمة المفتاح** (لا المفتاح) ③ أداة `npm run db:verify` ④ **رفض** القطعة التالفة/المستبدلة/ المفتوحة **قبل** لمس القاعدة ⑤ **قياس** زمن الاستعادة |
| ⭐ الاختبار | `tests/server/foundation-recovery.test.ts` · M-69a..M-69e (٥) + `foundation-backup.test.ts` (M-04a/b) |
| ⭐ النتيجة | **٩/٩** · زمن الاستعادة المقيس **≈ ٢٢٠ مللي ثانية** (RTO محلي) |
| ⭐ القيد المتبقّي | ⛔ **النسخ خارج المضيف تصميم فقط**: لم ينتقل أي ملف إلى Google Drive أو Railway أو أي خدمة خارجية · ⛔ المفتاح محلي (`.local/backup.key` · ٠٦٠٠) ⇒ **مدير الأسرار قرار مالك** · ⛔ لا **جدولة** نسخ (قرار مالك) |
