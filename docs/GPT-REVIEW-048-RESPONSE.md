## ٢. ⭐⭐ M85 — الأرقام والروابط (P1)

### ٢.١ ⭐⭐⭐ العيب المُثبَت (قبل)

⭐ **الملاحظة صحيحة** ⇒ ⭐ **والعيب كان حقيقياً وموثّقاً في الكود لا في الوصف**:

- ⭐ **`tools/print_gpt_msg.py::test_counts()`** كانت تشغّل `npm test` **حيّاً على شجرة العمل** وتُرجع الرقم (**٨٧٤** في هذه الجولة).
- ⭐ **و`summary_block(sha)` كانت تضع روابط على commit أقدم** (`73e47d7`) ⇒ ⭐ **فالقارئ كان يقارن رقماً حيّاً (٨٧٤) برابط commit توثيقه (٨٢٧)** ⇒ ⭐ **تعارض حقيقي في النص المنشور**.
- ⭐ **وأداة التدقيق (`tools/test_count_audit.py`) كانت تقارن «القسم الحالي» بمعلومة مشتقة من القرص** ⇒ ⭐ **ولم تكن تربط الرقم المنشور بالـcommit الذي يحمل الروابط**.

### ٢.٢ ⭐⭐ ما الذي أُصلح

| # | الإصلاح | الملف |
|:-:|---|---|
| ١ | ⭐ **`commit_partition(sha)`**: تقرأ `<!-- wasl:current-partition … -->` من **الـcommit نفسه** عبر `git show` ⇒ ⭐ **الرقم المنشور = رقم الـcommit المُثبَّت** | `tools/print_gpt_msg.py` |
| ٢ | ⭐ **المقارنة**: الرقم الحيّ يُقارن بالرقم الموثّق ⇒ ⭐ **وعند التعارض: ⛔ فشل ظاهر + سطر ⛔ في الرسالة + خروج غير صفري في `--check`** (لا نجاح كاذب) | `tools/print_gpt_msg.py` |
| ٣ | ⭐ **وضع صارم في الأداة**: `--commit` + سجلّ التشغيل + سجلّات المجموعات الأربع + تحقّق `pass + fail + skipped = tests` لكل سجلّ ولكل مجموعة + مطابقة علامة الـcommit | `tools/test_count_audit.py` |
| ٤ | ⭐ **فحص القرص مقابل `npm test`**: كل ملف `tests/**/*.test.ts` على القرص لازم يكون في `npm test` ⇒ ⭐ **فأداة M85 كشفت ملفَّين جديدين لم يكونا مسجَّلين** (⇒ نجاحهما المزعوم بلا أساس) ⇒ **أُضيفا** | `tools/test_count_audit.py` |
| ٥ | ⭐ **العلامة الصريحة** في `docs/TEST-MATRIX.md` و`CURRENT-STATE.md`: `<!-- wasl:current-partition 574 + 172 + 112 + 16 = 874 -->` | الوثائق |

### ٢.٣ ⭐⭐ الدليل (أوامر مُنفَّذة)

```
python3 tools/test_count_audit.py --docs --commit <sha> \
  --log <سجل npm test> \
  --group-log unit=<f> --group-log integration=<f> \
  --group-log security=<f> --group-log recovery=<f>
⇒ TEST COUNT AUDIT OK
```

⭐ **السلوك الجديد عند التعارض**: ⭐ **الفحص يطبع ⛔ ويخرج بغير صفر ⇒ ⇒ ⇒ لا يمكن أن يُنشر رقم غير مربوط بالـcommit دون أن يظهر الفشل**.
