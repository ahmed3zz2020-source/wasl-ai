## ⭐ ٢. الواجهة المطلوبة — خمس قدرات

> ⭐ **القدرات الخمس ليست اختيارية** ⇒ ⇒ **القناة التي لا تدعم واحدة تُعلن ذلك صراحةً في العقد** ⇒ ⇒ **ولا يُدّعى دعم ما لا يُدعم.**

| # | القدرة | المعنى | إجبارية؟ | ماذا يحدث لو غابت |
|:-:|---|---|:-:|---|
| ١ | ⭐ **استقبال** | ⭐ تحويل حدث خارجي (رسالة واردة) إلى عقد داخلي | ⭐ **نعم** | ⭐ القناة لا تصلح لخدمة العملاء ⇒ ⇒ **تُعلن «قناة صادرة فقط»** |
| ٢ | ⭐ **إرسال** | ⭐ تحويل رسالة صادرة إلى حدث عند المزوّد | ⭐ **نعم** | ⭐ القناة استقبال فقط ⇒ ⇒ **تُعلن كذلك** |
| ٣ | ⭐ **قالب** | ⭐ تعريف نصّ معتمد مسبقاً + حالة اعتماده | ⭐ **اختيارية** | ⭐ **الردّ الحرّ فقط** ⇒ ⇒ **وهو وضع مقبول لمحادثة داخل المنتج** |
| ٤ | ⭐ **حالة** | ⭐ حالة التسليم (أُرسل · سُلّم · فشل · رُدّ عليه) | ⭐ **اختيارية** | ⭐ **لا يُعرض للمستخدم حالة تسليم** ⇒ ⇒ **والنظام يقول «حُفظت ولم تُرسل»** |
| ٥ | ⭐ **معرّف فريد** | ⭐ معرّف ثابت يميّز الرسالة عند المصدر ⇒ ⇒ **ويُشتق منه `message_ref` داخلي** | ⭐ **نعم — وهي أهم قدرة** | ⭐ **لا منع تكرار ⇒ ⇒ ⇒ و`message_ref` يُولَّد عشوائياً ⇒ ⇒ ⇒ والتكرار ممكن ⇒ ⇒ ⇒ وهو خطر تشغيل حقيقي** |

> ⭐ **لماذا المعرّف الفريد هو الأهم**: ⭐ كل idempotency في النظام كله معلّق عليه ⇒ ⇒ `message_ref` هو معرّف التكرار الداخلي (`src/core/envelope.ts:8-9`) ⇒ ⇒ و`src/core/store.ts:109-123` يرفض به ⇒ ⇒ **فمحوّل بلا معرّف ثابت = محوّل يفتح باب تكرار الرسائل**.

## ⭐ ٣. عقد المحوّل (مواصفة — تُكتب في موجة لاحقة · بلا ملف الآن)

### ⭐ ٣.١ الأنواع

```typescript
// ============================================================
// WASL AI — عقد المحوّل (مواصفة · غير مُنفَّذ)
// ------------------------------------------------------------
// ⭐ لا حقل من أي مزوّد داخل هذه الأنواع.
// ⭐ أي سطر يحتاج حقلاً خاصاً بمزوّد ⇒ ⇒ ⇒ لا يدخل هنا.
// ⭐ القيم الخاصة بالمزوّد تُمرَّر في attributes (خريطة نصية).
// ============================================================

/** ⭐ معرّف القناة — نفس نمط حقل channel في العقد الداخلي. */
export type ChannelSlug = string;

/** ⭐ قدرات القناة — معلنة لا مُستنتجة. */
export interface ChannelCapabilities {
  readonly inbound: boolean;
  readonly outbound: boolean;
  readonly templates: boolean;
  readonly delivery_status: boolean;
  readonly stable_remote_id: boolean;
}

/** ⭐ حدث وارد — محوَّل من شكل المزوّد إلى شكلنا. */
export interface InboundEvent {
  readonly remote_id: string;          // ⭐ ثابت · لا يتغيّر بين المحاولات
  readonly conversation_remote_id: string | null; // ⭐ مرجع عند المصدر (إن وُجد)
  readonly from: string;               // ⭐ عنوان المرسل (نص · نمط العقد)
  readonly to: string;                 // ⭐ عنوان المستقبل (نص · نمط العقد)
  readonly body: string;
  readonly occurred_at: string;        // ⭐ ISO UTC بنمط العقد
  readonly locale: string;
  readonly attributes: Readonly<Record<string, string>>; // ⭐ ≤ 16 مدخلاً
}

/** ⭐ أمر صادر. */
export interface OutboundCommand {
  readonly message_ref: string;        // ⭐ معرّف التكرار الداخلي
  readonly conversation_ref: string;  // ⭐ من السياق الموثوق لا من المحتوى
  readonly to: string;
  readonly body: string;
  readonly locale: string;
  readonly template_ref?: string;      // ⭐ عند دعم القوالب فقط
  readonly attributes: Readonly<Record<string, string>>;
}

/** ⭐ نتيجة الإرسال — لا تُختزل في نجاح/فشل. */
export type SendOutcome =
  | { readonly status: 'accepted'; readonly remote_id: string | null }
  | { readonly status: 'deferred'; readonly reason: 'rate_limited' | 'temporarily_unavailable' }
  | { readonly status: 'rejected';  readonly reason: 'invalid_recipient' | 'policy_blocked' | 'template_missing' }
  | { readonly status: 'failed';    readonly reason: 'transport_error' | 'credential_invalid' };

/** ⭐ حالة التسليم — اختيارية: accompanies قدرات القناة. */
export type DeliveryStatus = 'sent' | 'delivered' | 'read' | 'failed';

/** ⭐ قالب — اختياري. */
export interface TemplateSpec {
  readonly template_ref: string;
  readonly body: string;
  readonly approval_state: 'draft' | 'pending_review' | 'approved' | 'rejected';
  readonly remote_template_id?: string;
}

/** ⭐ المحوّل نفسه. */
export interface ChannelAdapter {
  readonly channel: ChannelSlug;
  readonly capabilities: ChannelCapabilities;
  verifyInbound?(raw: unknown, headers: Readonly<Record<string, string>>): Promise<boolean>;
  receive(raw: unknown, headers: Readonly<Record<string, string>>): Promise<InboundEvent>;
  send(command: OutboundCommand): Promise<SendOutcome>;
  templates?(): Promise<readonly TemplateSpec[]>;
  deliveryStatus?(remote_id: string): Promise<DeliveryStatus | null>;
}
```

> ⭐ **ثلاث قواعد في العقد تعلو على كل ما عداه**:
> 1. ⭐ **لا حقل خاص بمزوّد** داخل الأنواع ⇒ ⇒ **وأي حاجة خاصة تُمرَّر في `attributes`** ⇒ ⇒ **و`attributes` محدودة بـ١٦ مدخلاً ومقيّدة بنمط (نفس قواعد العقد الداخلي)**.
> 2. ⭐ **الفشل يُنقل كقيمة لا كاستثناء** ⇒ ⇒ **فالمحوّل لا يقرّر مصير الرسالة** ⇒ ⇒ **والقرار في طبقة المعالجة** (`src/core/processing.ts`).
> 3. ⭐ **المعرّف البعيد ثابت** ⇒ ⇒ **وإلا انهار منع التكرار**.

### ⭐ ٣.٢ كيف يُترجم العقد الداخلي إلى عقد المحوّل (ربط هندسي)

| # | حقل العقد الداخلي | المصدر في المحوّل | ملاحظة |
|:-:|---|---|---|
| ١ | ⭐ `schema_version` | ⭐ **ثابت `'1'`** | ⭐ **لا يأتي من المزوّد** |
| ٢ | ⭐ `message_ref` | ⭐ **مشتقّ من `remote_id`** | ⭐ **أو `remote_id` نفسها إن كانت ضمن النمط `[A-Za-z0-9._:-]{1,64}`** ⇒ ⇒ **وإلا فاشتقّ مشتقّ ثابت** |
| ٣ | ⭐ `channel` | ⭐ **نُ slug المحوّل** | ⭐ **مطابق للنمط** |
| ٤ | ⭐ `direction` | ⭐ **`'inbound'`** للوارد · `'outbound'` للصادر | ⭐ من مجموعة مغلقة في العقد |
| ٥ | ⭐ `from` / `to` | ⭐ من المحوّل | ⭐ **مطابق لنمط العنوان في العقد** (`src/core/envelope.ts:68`) ⇒ ⇒ **وإلا فترميز ثابت** |
| ٦ | ⭐ `body` | ⭐ من المحوّل | ⭐ **حدّ ٤٠٩٦ محرفاً** ⇒ ⇒ **وإلا فالقصّ معلن لا الصمت** |
| ٧ | ⭐ `occurred_at` | ⭐ من المحوّل | ⭐ **ISO UTC** ⇒ ⇒ **وإلا فوقت الخادم** (معلَن) |
| ٨ | ⭐ `locale` | ⭐ من المحوّل | ⭐ **نمط اللغة في العقد** |
| ٩ | ⭐ `attributes` | ⭐ من المحوّل | ⭐ **≤ ١٦ · مفتاح بنمط · قيمة ≤ ٢٥٦ محرفاً** |
| ١٠ | ⭐ `conversation_ref` | ⭐ **من سجلّ الربط لا من المزوّد** | ⭐ **الأهم**: ⭐ «هذا حقل خام من المُرسِل ⇒ وجوده أو شكله لا يُثبت موثوقيته» (`src/core/envelope.ts:42-46`) |
| ١١ | ⭐ `declared_tenant_id` | ⭐ **من سجلّ الربط** | ⭐ **لا يُؤخذ من جسم الطلب** |

## ⭐ ٤. كيف يُستبدل المزوّد بلا تغيير النواة — أربع نقاط وصل

> ⭐ **المبدأ**: ⭐ **النواة تُلمس في صفر سطر** ⇒ ⇒ **وكل ما يتغيّر في تبديل المزوّد يقع في الطبقات الأربع التالية**.

### ⭐ ٤.١ نقطة الوصل الأولى — الحافة الواردة (استقبال)

| # | البند | اليوم | عند التبديل |
|:-:|---|---|---|
| ١ | ⭐ **المسار** | ⭐ **لا مسار استقبال خارجي** (قائمة المسارات لا تحوي `webhook`) | ⭐ **مسار جديد واحد** يقرأ الجسم **خاماً** ⇒ ⇒ **ثم يمرّره إلى المحوّل** |
| ٢ | ⭐ **التحقّق** | ⭐ **لا يوجد** | ⭐ **`verifyInbound` في المحوّل** ⇒ ⇒ **فالمحوّل وحده يقرّر رفض التوقيع** |
| ٣ | ⭐ **منع إعادة الإرسال** | ⭐ **لا يوجد** (لكن النواة فيه منع تكرار) | ⭐ **النافذة الزمنية في المحوّل** + ⭐ **منع التكرار في النواة** (`message_ref`) ⇒ ⇒ **طبقتان لا واحدة** |
| ٤ | ⭐ **من يمرّر المستأجر** | ⭐ — | ⭐ **سجلّ الربط: (المزوّد · المعرّف البعيد) ⇒ ⇒ (المستأجر · المحادثة)** ⇒ ⇒ **وليس من جسم الطلب** |

### ⭐ ٤.٢ نقطة الوصل الثانية — الحافة الصادرة (إرسال)

| # | البند | اليوم | عند التبديل |
|:-:|---|---|---|
| ١ | ⭐ **مسار الإرسال** | ⭐ `POST /api/inbox/conversations/{ref}/replies` | ⭐ **نفس المسار** ⇒ ⇒ **يتغيّر ما خلفه فقط** |
| ٢ | ⭐ **القناة** | ⭐ `channel: 'web'` ثابتة | ⭐ **من سجلّ الربط لا من المتصفح** ⇒ ⇒ **وإلا أمكن لمتصفح أن يختار قناة غير محفوظة** |
| ٣ | ⭐ **المستقبِل** | ⭐ `to: 'customer@example.invalid'` | ⭐ **عنوان فعلي من سجلّ الربط** ⇒ ⇒ **وعنوان غير معروف = رفض لا إرسال وهمي** |
| ٤ | ⭐ **نتيجة الإرسال** | ⭐ `sent: false` دائماً | ⭐ **من المحوّل** ⇒ ⇒ **و`accepted` يعني «قُبل عند المزوّد» لا «وصل»** |
| ٥ | ⭐ **المحاولة مرّة** | ⭐ **التكرار مرفوض** | ⭐ **نفس المرجع** يُعاد ⇒ ⇒ **فالإرسال لا يتكرر** ⇒ ⇒ **والمزوّل الذي يقبل قبل أن يرد ⇒ ⇒ يتكرّر ⇒ ⇒ فالحماية عند المزوّد لا عندنا** |

> ⭐ **الأهم في البند ٥**: ⭐ منع تكرار الإرسال **عندنا** يغطي حالة «الطلب ضاع» ⇒ ⇒ **لكنه لا يغطي «قبل المزوّد أن يرد»** ⇒ ⇒ **فهذا يحتاج تتبّع حالة الإرسال على مستوى المزوّد** ⇒ ⇒ **وهو بند منفصل ولا يُختزل في `message_ref`**.
