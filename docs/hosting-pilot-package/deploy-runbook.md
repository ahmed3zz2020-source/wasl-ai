| # | الفحص | الأمر | ما يثبته | إن فشل |

> ⭐ **ملاحظة على `git status`**: ⭐ **المستودع فيه اليوم ملفات غير متتبَّعة من أعمال متوازية** — ⭐ **فهذا الفحص متوقّف فعلياً حتى تُحسم حالة الشجرة**.

## ⭐ ٣. خطوات النشر

| # | الخطوة | الأمر / الإجراء | ملاحظات |
|:-:|---|---|---|
| ١ | ⭐ **تصدير الأسرار** | ⭐ **تصدير يدوي من خارج المستودع** | ⭐ ⛔ `WASL_PG_SUPERUSER_URL` يحمل اعتماداً — في صدفة المشغّل فقط |
| ٢ | ⭐ **تهيئة القاعدة** | ⭐ `npm run db:setup` | ⭐ ينشئ الدورين ويطبّق الهجرات ويزرع البذور — ⭐ ⚠️ الأداة تربط `127.0.0.1` |
| ٣ | ⭐ **نسخة احتياطية قبلية** | ⭐ `npm run db:backup` | ⭐ تكتب في `.local/backups/` — ⭐ للتحقق منها: `npm run db:verify -- <artifact>` |
| ٤ | ⭐ **تشغيل الخادم** | ⭐ `npm run server` | ⭐ أو حاوية من `Dockerfile` — ⭐ ⚠️ ديمون `Docker` غير متاح هنا (`pf-22` BLOCKED) |
| ٥ | ⭐ **فحص الجاهزية** | ⭐ `GET /ready` | ⭐ يفحص القاعدة والمخطّط — ⭐ `503` عند تعطّل القاعدة |
| ٦ | ⭐ **`TLS` والوكيل العكسي** | ⭐ `deploy/nginx.conf.example` كمرجع | ⭐ ⚠️ ملف مثال لم يُحمَّل — ⭐ الشهادة والمفتاح خارج الشجرة |
| ٧ | ⭐ **تحقق خارجي** | ⭐ `GET /health` من خارج الجهاز | ⭐ **هذا هو دليل `pf-16`** |

> ⭐ **قاعدة الطلب**: ⭐ **`/ready` قبل `/health`** — ⭐ `/health` يجيب عن «العملية حيّة»، و`/ready` يجيب عن «الخدمة تستطيع الخدمة».
