⭐ **نُفِّذت الحزمة محلياً بالكامل داخل حدود التصريح**: Backend حقيقي فوق النواة القائمة، PostgreSQL محلية مع عزل على مستوى الصفوف، جلسات وأدوار تجريبية، محرك خصوصية قابل للاختبار، ورحلة End-to-End تمرّ عبر HTTP وقاعدة البيانات فعلياً.

## ١. البيئة والتشغيل (AC-01)

| العنصر | القيمة المقيسة |
|---|---|
| نظام التشغيل | Debian 12 (amd64) |
| Node.js | v22.19.0 · npm 10.9.3 |
| PostgreSQL | **15** (من حزم Debian الرسمية، تشغيل محلي على `127.0.0.1:5432`) |
| المتصفّح | Chromium (Playwright) — لاختبار الواجهة المحلية |
| اعتمادية جديدة | `pg` ٨.٢٣.١ فقط (سائق PostgreSQL) — سطر واحد في `devDependencies` |
| اتصال خارجي | **صفر**: فحص ثابت على `server/` + حاجز وقت تشغيل يرفض أي مقبس خارج Loopback |

### أوامر التشغيل (قابلة لإعادة الإنتاج)

```bash
# ١) تهيئة قاعدة البيانات (أدوار + migrations + بيانات صناعية)
npm run db:setup

# ٢) تشغيل الـBackend المحلي
npm run server          # http://127.0.0.1:8787  (الواجهة: /ui/index.html)

# ٣) الرحلة الكاملة عبر HTTP
npm run e2e

# ٤) كل الاختبارات (السابقة + الجديدة)
npm test
```

⭐ `db:setup` **قابل لإعادة التشغيل**: الـmigrations idempotent والـseed يعيد بناء البيانات الصناعية.

⛔ **نقطة إعداد واحدة خارج المستودع**: كلمة مرور دور `postgres` (المشرف) تُضبط مرة واحدة على المضيف، والسجل يقرؤها من `WASL_PG_SUPERUSER_URL` — لا تُخزَّن في المستودع إطلاقاً.

⭐ **الأسرار**: كلمتا مرور الأدوار تُولَّدان عشوائياً عند كل تهيئة وتُكتب في `.local/pg-credentials.json` (مُستبعَد من git بـ `.gitignore`) ⇒ **لا سرّ داخل المستودع ولا في السجلات ولا في لقطات الاختبار** (AC-14).

## ٢. ما تم تنفيذه فعلاً (بالمسارات والملفات والـcommits)

### المسار A — Backend محلي حقيقي فوق النواة

| الملف | الدور |
|---|---|
| `server/api/server.ts` | خادم HTTP على ١٢٧.٠.٠.١ · تحقق من المدخلات · أخطاء آمنة · سجل أحداث · رفض العمليات غير المصرّحة |
| `server/db/unit-of-work.ts` | معاملة واحدة لكل طلب + سياق المستأجر (`set_config`) ⇒ الذرّية والإلغاء التلقائي |
| `server/db/repositories/core-bundle.ts` | «حزمة» لكل مستأجر: نواة تقرأ الحالة وتقرّر، مع التقاط ما أخرجته النواة فقط |
| `server/db/repositories/persistence.ts` | كتابة ما أخرجه النواة في PostgreSQL داخل نفس المعاملة +hydration +إعادة التهيئة بعد الفشل |

⭐ **لم تُنسخ أي قاعدة عمل**: كل قرار (الصلاحية · الانتقالات · التحقق من الرسالة · حراسة الإغلاق) صادر من `src/core/` كما هو. الطبقات الجديدة تسجّل وتخزّن فقط.

### المسار B — PostgreSQL محلية وعزل الشركات

| الملف | الدور |
|---|---|
| `server/db/migrations/001_foundation.sql` | ١١ جدولاً + RLS مفعَّل و**مُجبَر** على كل جدول مستأجر + منح بأقل صلاحية |

- **العلامة**: `config.ownerDatabaseUrl` كان يستخدم كلمة مرور `wasl_app` بينما دور `wasl_owner` له كلمة مرور مستقلة ⇒ أي اتصال بالمالك من هذا الرابط يفشل في المصادقة.
- **السبب الجذري**: `readCredentialFile` كان يُرجع كلمة مرور واحدة فقط (كلمة مرور الطلب) ⇒ وأمر التهيئة `db:setup` يولّد سرّين منفصلين لكل دور.
- **الإصلاح**: `server/config.ts` يقرأ `app_password` و`owner_password` من ملف الأسرار، ويبني رابط الطلب من الأولى ورابط المالك من الثانية، مع `WASL_PG_OWNER_PASSWORD` كمتغيّر بيئة اختياري.
- **الدليل (R-01)**: الاتصال عبر `config.ownerDatabaseUrl` يعيد `current_user = wasl_owner` · ودور الطلب `wasl_app` يعيد `rolbypassrls = false` · `rolsuper = false`.

### العيب ٢ — رحلة E2E كانت تعتمد على ترتيب الأوامر

- **العلامة**: `npm run e2e` بعد `npm test` ⇒ فشل ٤٠١ عند الخطوة الأولى (تسجيل الدخول) — لأن اختبار الخصوصية يحذف عضويات الشركة على النطاق `tenant_full` (وهذا سلوك موثّق وصحيح في محرك الخصوصية).
- **السبب الجذري**: أداة الرحلة كانت تقرأ القاعدة كما هي ⇒ لم تكن تطبّق البذور الصناعية قبل الرحلة.
- **الإصلاح**: `tools/wasl-e2e-journey.ts` يطبّق الـmigrations والبذور الصناعية قبل كل رحلة (نفس سلوك الـharness) ⇒ الرحلة لا تعتمد على ترتيب الأوامر.
- **الدليل**: `npm test` ثم `npm run e2e` في نفس الجلسة ⇒ `JOURNEY OK` (١٥/١٥) · وقبل الإصلاح كانت النتيجة ٤٠١ عند الخطوة الأولى.

### العيب ٣ — البذور الصناعية كانت لا تُحدّث بصمة كلمة المرور

- **العلامة**: تغيير `WASL_TEST_PASSCODE` ثم إعادة `db:setup` ⇒ تسجيل الدخول يفشل رغم أن الأمر موثّق بأنه «آمن للتشغيل مرة أخرى».

- **الإصلاح**: `server/db/setup.ts` يحدّث `passcode_hash` مع بقية الحقول ⇒ البذور تُعيد بناء هوية الدخول الصناعية دائماً.
